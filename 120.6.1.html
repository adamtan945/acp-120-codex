官方目標 6.1 · 來源內容版 2026-10-05.complete-draft

先看懂這張圖

括號與空值決定查詢集合

JQL用欄位、運算子與值描述要找的工作。先在小範圍驗證一條條件，再加入AND／OR與排序；!=通常不包含空值，括號決定OR的範圍。查到的結果仍只限使用者可讀資料。

用一個例子理解

三筆合成Bug：LAB-101標籤lab-jql、承辦甲；LAB-102同標籤、未指派；DOC-101同標籤、未指派。需求只找LAB中不是甲或未指派的工作，正確集合應含LAB-102而不含DOC-101。

閱讀前提

不需要程式經驗。先認識project、status、assignee、created、labels是不同欄位。

所有範例專案key LAB、DOC與自訂欄位ID都是合成；若另行練習只查自己的授權測試資料。

範例保留考綱的project、issue語法；新UI用space/work item不代表要把所有舊JQL強制改名。

動手驗證

三筆資料驗證!=、EMPTY與括號

文件查核設計；未租戶實測。完成下列步驟後，以你看到的結果判斷是否成功。

這次要驗證

  • 先預測：!=目前使用者會包含未指派嗎？
  • 先預測：OR不加括號會改變專案範圍嗎？

準備環境

角色
  • 核准測試甲有LAB與DOC Browse、Create、Edit及Assign work items，且在LAB為Assignable user；不需Jira管理權。
方案與功能
  • Jira Cloud基本搜尋；沿用舊JQL欄位project／issue可兼容名稱rollout。
先備與假資料
  • 三筆上述合成資料與標籤lab-jql；只在獨立教學專案，甲以自己的測試登入執行currentUser。
  • 介面分批推出可能顯示專案（project／space）、工作項目（issue／work item）、工作類型（issue type／work type）；依物件與官方文件辨認入口。
隔離範圍
  • 僅限已核准獨立教學站台的LAB專案（project／space）；資料、名稱與測試身分均為合成，不連正式站台。
  • 只用既有核准測試帳號，不邀請真實人員；測試站台須預先隔離郵件、外部整合與非實驗automation，未確認隔離時改用紙上模式。

先預測：!=目前使用者會包含未指派嗎？

比較預測與理由

一般!=不匹配空值，需要OR assignee IS EMPTY。

先預測：OR不加括號會改變專案範圍嗎？

比較預測與理由

會；AND先結合，OR的空值分支可能不受原project條件約束。

記住這個心像 先定義集合，再用括號寫邊界；排序不改變資料權限。

深入查閱

把圖中的關係對回設定

以下保留本節考點與細節。沿用圖中的角色、假資料與步驟，逐段確認原因。

先認識名詞

JQL Jira Query Language：Jira的結構化搜尋語言，選出符合條件且你有權讀取的工作項目。它不是資料庫SQL，不用SELECT，也不會因搜尋而修改資料。

Clause 子句：一個欄位＋運算子＋值或函式所構成的條件。

Operator 運算子：表達相等、集合、空值、大小或文字比對的方法。

Function 函式：依執行上下文產生值，例如目前使用者或今日起點。

EMPTY／NULL：表示欄位沒有值，與空白字串、零或名為Unresolved的自訂選項不同。

先寫一句中文 再拆成三個部分

需求「找LAB專案的工作」可寫project = LAB。project是欄位，=是運算子，LAB是值。想再限制由自己承辦，寫project = LAB AND assignee = currentUser()。AND表示兩個條件都成立；每加一個AND是在原範圍內再縮小，不是建立另一份資料。

在Search→View all work items切到JQL，先輸入單一條件並執行，再逐步加入下一條。搜尋結果是目前使用者可以看到的資料，不是整站資料庫總表。沒有結果可能是資料不符合、沒有權限，或欄位用錯；語法合法不等於業務需求寫對。

單值含空格時用引號，例如status = "In Progress"。本教材在操作邏輯中保留英文欄位，中文說明教你讀懂用途。ORDER BY created DESC放在整個條件最後，只改排序，不會把原本不符合的工作加進來。

選對欄位與欄位身分

系統欄位包括project、assignee、status、created與summary。自訂欄位是管理者為業務加的資料，例如單選「Delivery Region」、數字「Review Score」。先確認它的型別與使用範圍：數字可以比較大小，文字通常走文字搜尋；畫面上名字相似不代表資料型別相同。

自訂欄位可以用名稱或cf[ID]查詢，例如cf[10420] = "North"。ID能避免兩個同名欄位造成選錯；10420只是合成例子，不能拿到任何站台就以為相同。若欄位context不包含LAB或該工作類型，查詢合法也可能沒有預期資料。

練習設計：已知cf[10420]是單選Delivery Region，cf[10421]是數字Review Score，summary是文字。

三個不同需求分別是cf[10420] = "North"、cf[10421] >= 3、summary ~ "printer"。不要把「文字看起來像數字」當成數值型別，也不要用文字CONTAINS搜尋單選選項。

運算子要配合欄位型別

不能把「不是甲」的中文直接當成包含空值。

=找符合單一值；IN (A, B)表示符合集合中的任一值。例如project IN (LAB, DOC)等同兩個project條件用OR連接。!=和NOT IN排除特定已存在的值，但不會自動把無值的工作算進來。

若要包括未指派，應明寫assignee != currentUser() OR assignee IS EMPTY。

IS EMPTY／IS NULL測無值；IS NOT EMPTY測有值。不要把NULL放在引號裡當字串，不要把resolution != Done當成「未解決」的通用寫法。Resolution有值卻不是Done，也可能已用其他原因結案；

要找未設定Resolution，應明確用resolution IS EMPTY並確認該專案欄位模型。

summary、description等文字欄位通常使用~或!~，不是一般=。日期或數值支援>、>=、<、<=等排序比較。WAS和CHANGED是歷史查詢用途，只有特定欄位支援，不能因為所有工作都有歷程就拿任意自訂欄位使用。

確認官方field reference的supported operators比死背符號更可靠。

函式回傳的值也有型別

currentUser()不需要參數，代表這次執行查詢的登入使用者，常用assignee = currentUser()。

membersOf("lab-reviewers")需要一個存在的群組參數並產生人員集合，所以配assignee IN membersOf("lab-reviewers")，不是把集合塞到單值=。

startOfDay()產生今日起點；startOfDay("-1d")產生昨日的日期起點，startOfMonth("-1")則以月為自然單位向前。函式括號不是隨意裝飾，參數名稱與時間單位要符合該函式。

currentUser("Ari")不是選定Ari的方法；如果要查固定人員，應以站台可用的帳號ID或明確使用者值查詢。

練習判斷先問三件事：左側是什麼型別？函式回傳一個值或多個值？該欄位／函式支援哪個運算子？membersOf可用於使用者欄位，不應拿來查created。日期函式可用於日期欄位，不應以summary = startOfDay()尋找今天的文字。

括號讓需求範圍一眼看得懂

AND比OR先結合，完整優先序是括號、比較、NOT、AND、OR。官方進階搜尋概覽有一句簡化的left-to-right，專門Cloud優先序文件則明確列出上述順序。本課採專門文件，並以括號明示意圖，避免靠語感解讀長條件。

需求「LAB內，指派給我或還沒有人接手」應寫project = LAB AND (assignee = currentUser() OR assignee IS EMPTY)。

若漏括號，project = LAB AND assignee = currentUser() OR assignee IS EMPTY會等同(project = LAB AND assignee = currentUser()) OR assignee IS EMPTY，於是其他專案的未指派工作也可能進來。

用三筆合成資料手算：LAB-1由我承辦、LAB-2未指派、DOC-1未指派。正確括號式回傳LAB-1與LAB-2；漏括號式還多DOC-1。這不是搜尋引擎亂抓，是你把最後一個OR放到整體範圍。每次改括號都應用至少一筆「應該入選」與一筆「不該入選」的反例驗證。

時間範圍用下界包含 上界不包含

要查2026年9月建立的資料，先指定時區，再用created >= "2026-09-01" AND created < "2026-10-01"。這個半開區間包括9月1日午夜，也包括9月30日任何時間，但不包括10月1日午夜。

比寫「<= 9月30日」更不容易漏掉最後一天，因為沒有時分的日期按午夜解讀。

相對時間與日曆邊界不同：created >= "-7d"是相對執行時間往前七天；created >= startOfDay("-7d")從七天前的日開始。若現在是15:00，兩者下界可相差15小時。

要查昨日全天，使用created >= startOfDay("-1d") AND created < startOfDay()。

日期與時間搜尋依設定時區解讀。跨地區團隊應先約定用哪個時區，再評估邊界資料。不要將due純日期的概念和created日期時間混在一起，也不要靠畫面顯示的年月日推斷UTC時刻。本課時間題會把時區與精確資料完整給定。

只寫created >= startOfMonth()是本月起至目前存在的符合資料，不等同一份永遠固定的月報。要重跑歷史報告，保存明確起迄日期；要每日自動更新視圖，才使用相對函式。這是查詢設計目的的選擇，不是語法誰比較高級。

不能切回基本搜尋 不代表JQL錯誤

基本搜尋表單能表達的條件有限。複雜OR、NOT、EMPTY、某些比較運算子，或使用專案相依欄位卻未指定專案，可能無法轉回Basic。project IN (LAB, DOC)可能可由基本表單表達，與任意跨欄位OR並不相同。

看到語法錯誤時，先縮小到一個已知正確子句，再確認欄位名稱／ID、運算子支援、引號、括號配對與函式參數。看到語法合法但結果錯時，先檢查需求邏輯、無值處理、日期邊界與目前身分。這兩種錯誤不要用同一種修法。

練習不需要在Jira新增資料：用本課合成卡片先判斷入選，再寫查詢。即使使用自動產生JQL的工具，仍需用反例與邊界驗證；AI寫出的合法語法不是業務結果保證。生成工具本身屬於額外背景，ACP-120本課要建立的是你能自行解釋搜尋的能力。

圖解與逐步理解

有括號

project = LAB AND (assignee = currentUser() OR assignee IS EMPTY) 限制全部承辦條件。

無括號

project = LAB AND assignee = currentUser() OR assignee IS EMPTY 可能納入其他專案空值。

含起點

九月區間包含 9 月 1 日起點。

排除終點

以小於 10 月 1 日起點排除下月資料。
