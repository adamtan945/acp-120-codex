先認識名詞

Name：方便閱讀與辨識的專案名稱。

Project key／space key：出現在工作項目識別碼與網址中的專案短代碼。

Work-item key：例如MOB-42，組合專案key與編號。

Project lead／space owner：專案負責人資訊，可被預設指派引用，不是所有管理權限的同義詞。

名稱、key 與工作項目 key，分別負責什麼

專案名稱是方便人理解的標籤，例如「行動版產品」；專案 key 是短識別碼，例如 MOB；工作項目 key 則由專案 key 與編號組成，例如 MOB-42。名稱、專案 key 與工作項目的摘要不是同一欄，不要把改名當成改每一筆工作內容。

key 常出現在網址、JQL、報表、聊天訊息、外部整合與文件中，所以它的影響超出專案首頁。修改前應先盤點哪些位置用名稱或 key 識別專案。能在 Jira 內正常開啟，不代表外部工具裡的文字、匯出的檔案或自寫查詢也都同步更新。

專案管理頁的 Details／詳細資料會集中呈現名稱、key、說明、網址、類別、負責人等可用資訊；實際欄位與可編輯權限依管理型態與目前介面而異。說明適合寫用途與聯絡方式，不能拿它當作權限控制。專案 URL 若指向外部網站，也不表示將工作資料搬到該網站。

編輯專案資訊時，先確認欄位用途與管理權限

先從專案的 Space settings／Project settings 找到 Details，閱讀目前名稱、key、負責人及其他資訊。不要直接沿用記憶中的舊UI座標；以功能名稱及頁面用途辨識。若某個欄位不可修改，先查角色與該欄位的限制，而不是反覆嘗試不同頁面。

目前官方文件特別指出，更改 key 需要組織管理員、站台管理員或 Jira 管理員等相應管理角色，不能因為能改一般專案資訊就推論也能改 key。改名與改 key 是不同操作，應分別確認授權與影響。

專案負責人（project lead／space owner）是專案資訊與部分預設指派邏輯使用的身分，不等同給這個人所有管理權限。預設承辦者若設為負責人，改負責人可能改變往後採用此預設值的指派結果，詳見2.4。

導覽的目的是讓人找到正確資訊。名稱與說明要清楚，相關連結應指向正確位置；但新增導覽連結不會賦予使用者對目標資源的權限。對方仍需有底層專案、工作項目或外部文件的存取資格。

改名與改 key：內建相容行為不能取代影響評估

官方文件描述，專案名稱變更後，Jira 內部相關 filter 會自動更新。但不要把這項內建行為擴張成「全世界所有含舊名稱的文字都會更新」。匯出報表、試算表、自寫腳本與外部文件是另一個範圍。

更改專案 key 時，工作項目會改用新的 key 前綴；舊 key 在保留相應歷史記錄的條件下可繼續導向對應工作項目。這能降低既有連結失效的風險，但不代表所有外部系統都理解別名，也不代表可以永久保證已移除的歷史 key 仍有效。

現行文件另有移除先前 key 的管理方式。移除舊 key 會牽涉舊連結／參照與重新使用 key 的需求，不能把「改key」與「清除舊key」視為同一件事。本課不要求在實際站台刪除歷史 key，只要求能解釋兩者風險不同。

變更檢查清單至少包含：新 key 的工作項目能否開啟、保留的舊連結是否仍導向正確項目、JQL與board篩選條件、外部整合對應、文件與匯出資料。若某個系統尚未實測，應明確寫「未驗證」，而不是用 Jira 的內建重導推論它一定正常。

情境：品牌改名，需要改哪些東西

假設專案名稱從「舊版會員平台」改成「會員體驗」，團隊只想讓首頁與清單更容易辨識，沒有要求改短代碼。先評估只改名稱是否已滿足需求；不必把每次名稱變更都擴大成 key 變更。

若另有系統整併要求，必須把 MEM 改成 CX，則由具相應權限的人規劃，保留舊值與引用清單。在隔離環境以一個工作項目檢查新舊連結、JQL、board和整合測試資料；不能用真實敏感工作項目作為教材示範。

當某人說「我看不到更新後的專案」，先問他是找不到名稱、舊連結錯誤、filter結果不符，還是沒有Browse權限。命名、查詢、導覽與授權是不同原因，要用觀察到的症狀逐一排除。

常見誤解：一個名稱變動，不代表每個系統都懂

錯誤說法：「改專案名稱必須同時改key。」釐清：兩個欄位用途不同，應依需求決定。

錯誤說法：「只要舊連結還能開，所有整合就一定沒有影響。」釐清：各系統的識別與快取方式不同。

錯誤說法：「專案負責人就是組織管理員。」釐清：資訊欄位不等於帳號管理角色。

錯誤說法：「把連結放進導覽，就給了對方存取權。」釐清：導覽與授權分開。

圖解與逐步理解

只改名稱

名稱與 key 分別管理；更名不是改 key。

改 key

核對內建引用、先前 key 與新識別，不假設外部工具都自動更新。

外部引用

外部腳本、連結與整合需要另行驗證。

自我檢查與理由

自我檢查

MOB-42 中，MOB 和42各代表什麼？

查看答案與理由

MOB是專案key，42是該工作項目的編號部分；不是專案名稱與狀態。

自我檢查

更改專案負責人，就等於把他加入所有管理員角色嗎？

查看答案與理由

不是。負責人欄位與管理權限是不同設定；預設指派可能引用負責人，但不因此授予所有權限。

自我檢查

改key後舊工作項目連結能重導，可以因此略過外部整合檢查嗎？

查看答案與理由

不行。Jira內建相容行為與外部工具的識別邏輯不同；需要分別盤點與驗證。
