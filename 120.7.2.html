先看懂這張圖

附件、工時與連結各有自己的門

系統功能啟用、欄位配置與專案操作權限都影響能否使用附件、工時與連結。三項不能只查同一個全站開關；Link type的向外與向內描述是同一關係的兩個視角，導航URL又不等於AppLink整合。

用一個例子理解

LAB-121有1KB合成note.txt、預估2h並紀錄30m；它blocks LAB-122，122顯示is blocked by 121。資料都是假值，本練習不改附件大小、工時單位或全站連結類型。

閱讀前提

理解全站功能、專案權限、欄位／screen與board是不同設定層。

所有上傳、工時填寫及整合在本課都只用紙上資料，不修改真實Jira。

動手驗證

三項假資料驗證使用層能力

文件查核設計；未租戶實測。完成下列步驟後，以你看到的結果判斷是否成功。

這次要驗證

  • 先預測：Browse就具有三項修改權限嗎？
  • 先預測：121 blocks 122是否應在122看到blocks 121？

準備環境

角色
  • 測試甲具Browse、Edit work items、Attach files、Work on work items與Link work items；復原自己的假工時另需Delete own work logs。
  • LAB管理員已核准功能與欄位，不修改全站功能。
方案與功能
  • Jira Cloud；附件需有剩餘儲存、工時欄位已可用、既有blocks類型已存在。
先備與假資料
  • Time tracking、Original estimate、Remaining estimate已在LAB可用；記錄兩估算原值與原工作連結。所有權限已核准，缺項即改紙上。
  • LAB-121/122均合成，所有步驟限這兩筆；本地1KB note.txt只寫LAB fake，文件名無個資；郵件已隔離。
  • 介面分批推出可能顯示專案（project／space）、工作項目（issue／work item）、工作類型（issue type／work type）；依物件與官方文件辨認入口。
隔離範圍
  • 僅限已核准獨立教學站台的LAB專案（project／space）；資料、名稱與測試身分均為合成，不連正式站台。
  • 只用既有核准測試帳號，不邀請真實人員；測試站台須預先隔離郵件、外部整合與非實驗automation，未確認隔離時改用紙上模式。

先預測，再驗證

先預測：Browse就具有三項修改權限嗎？

比較預測與理由

不具有；Attach、Work on與Link需各自檢查。

先預測：121 blocks 122是否應在122看到blocks 121？

比較預測與理由

應看到對應向內描述is blocked by 121，方向不可倒置。

記住這個心像 功能可用、資料可讀與動作可做分三層查，每項能力有不同條件。

還原與收尾

  • 只移除121/122本次教學連結；在Activity→Work log確認自己的LAB fake紀錄後移除該30m紀錄，核對並恢復Original／Remaining estimate原值。缺Delete own權限時由核准管理者復原，不動他人紀錄。
  • 假附件保留標註教學用途，不刪除正式檔案或全站link type；不改全站容量、單位與AppLinks。

沒有支援的環境：無權限或無教學站台：觀察／紙上替代

  • 依本章官方來源辨認設定物件；只看文件，不在自己的正式站台尋找替代操作。
  • 在紙上列出本章假資料、每一步預測與可見結果，再逐項核對checks答案。

深入查閱

把圖中的關係對回設定

以下保留本節考點與細節。沿用圖中的角色、假資料與步驟，逐段確認原因。

先認識名詞

Attachment：附在工作項目的檔案；新增、刪除與閱讀有不同條件。

Original estimate／Remaining estimate／Time spent：原估算、剩餘估算、已記錄工時，三者回答不同問題。

Worklog：一次記錄的實際工作時間與相關說明。

Link type：工作項目之間的關係種類，含向外及向內描述。

AppLink／App navigator link：前者連接應用功能及認證，後者提供導覽捷徑。

附件要同時通過功能 大小與權限

附件通常讓團隊保留截圖或規格。Jira Cloud預設啟用附件，但仍可在Settings→System→Advanced→Attachments檢查全站設定。Create Attachments決定誰能新增；Delete Own Attachments決定誰能刪自己上傳的檔，不代表可刪別人的檔。

建立工作時Attachment欄位也不能被field configuration隱藏。

單檔大小與整體儲存額度不同。查核日文件預設單檔上限1GB、最大可設2GB；站台方案另有儲存額度。郵件匯入的單封25MB又是獨立限制，因此把全站上限提高不會讓所有25MB以上郵件自動可處理。這些數字是版本化產品資訊，正式作業需重查。

合成排錯：50MB圖片低於設定的100MB單檔上限，別人能上傳但測試員甲不行。先比較Create Attachments與欄位設定，不要立刻提高全站上限。若全員只能在建立畫面找不到附件，則先查該work type使用的Attachment欄位是否被hidden。

估算與紀錄實際工時不要混在一起

Original estimate是開始時的估計，Remaining estimate是目前預估還要多少，Time spent彙整已記錄的實際工時。Story points則是相對估算，不能隨意視為小時。想讓團隊記實際工時，要檢查Work On Work Items及Time tracking欄位；

想讓Scrum報表以點數估算，則另查board估算設定。

現行Cloud具體文件說time tracking一直啟用：company-managed以field configuration顯示／隱藏Time tracking，team-managed以work type新增／移除該欄位控制使用。

文件前言仍有disable/re-enable歷史措辭，不能因此教一個不存在於當前路徑的全站停用按鈕。

若要在create/edit輸入original estimate，company-managed需要相關screens包含Time Tracking。

全域設定在Settings→Work items→Time Tracking，定義每天工作時數、每週天數、顯示格式與未指定單位時的default unit。這是在定義時間的輸入／顯示規則，不等於設定每位員工的值班日曆。

board上的估算方式是另一個設定

Company-managed Scrum的Board settings→Estimation可選估算方法與追蹤方式，具備board admin或board所在專案的管理者能力才可調整。此路徑文件明確限制company-managed Scrum，不可把同一操作聲稱適用所有Kanban board。

Team-managed的估算功能在Space settings→Features→Estimation，選Story points或Time。這與讓某使用者可新增worklog不同。初學者看到「Time」文字時，應先確認它是在board估算、工作項目欄位，還是全域time tracking單位。

合成團隊用Story points比較不同Task的相對大小，同時用worklogs追蹤實際花費。這兩種資料可以共存，但不能說把board估算改Time就自動把8點轉8小時；輸入數值的業務意義需先與團隊定義。

工時有問題時逐層檢查

看不到Log work時，先查該人能否閱讀工作、Work On Work Items，接著查Time tracking欄位在company-managed field configuration或team-managed work type中的可用性。

若只是create/edit看不到original estimate，另查screens。不要把所有問題都歸咎於全站開關。

「輸入2，卻比預期大很多」要查default unit：若預設是Day，沒寫單位的2可能代表兩個工作日。明寫2h可避免混淆。假設全域一天8小時，1d代表8h；若團隊說的天是24小時日曆天，就必須在輸入規範中澄清，不能把Jira的工作日換算當成全天。

「board圖表與工時不同」再查board估算與追蹤方法；「某worklog不能編輯／刪除」則查該類專案權限。先辨識是輸入、呈現、報表還是修改權限，再決定查哪個設定，能避免改動不相關配置。

一條工作連結有兩個方向

兩個描述表達同一條關係，不是兩次重復建立。

例如LAB-1 blocks LAB-2，從LAB-2看就是is blocked by LAB-1。Link type同時有Name、Outward description、Inward description；它們說明方向，不是建立兩條互相重複的關係。設定錯方向會讓依賴閱讀與JQL判讀混亂。

Jira管理者在Settings→Work items→Work item linking確認ON並建立類型；使用者還需Link Work Items權限與適當可見性。全域開啟不代表每個人都能操作；專案有權限但全站關閉也不能使用。

更名可能影響以link type文字搜尋的JQL。刪除link type時，產品會讓管理者選擇改成另一類型或移除相關連結，因此這不是單純移除下拉選項。官方也不建議隨意改clone連結類型。練習只畫向內／向外關係，不刪除真實類型。

導覽捷徑不會建立整合或權限

本lab不創建AppLink、OAuth或外部連線。

App navigator加入名稱與URL，是讓人更容易去某個網站；可依群組顯示或Hide。隱藏捷徑不會取消目的站權限，顯示捷徑也不會讓本來沒權限的人登入。各應用的導覽可見性可能需分別設定。

AppLinks則是讓應用之間交換資料或整合功能，例如在Jira看相關開發資訊；牽涉認證、遠端帳號權限及連線條件。OAuth流程與可能的持續存取必須由有權人員核准，本課不會建立認證、開網路或輸入憑證。

需求「在選單加公司手冊入口」通常是navigator link；需求「從Jira讀取另一Atlassian應用的相關資訊」才要評估受支援整合／AppLink。某些AppLink會自動出現在navigator，但這不表示兩種設定相同。

附件／工時先查功能是否啟用。

專案權限

功能啟用仍須相關使用權限。

欄位與估算

核對欄位呈現；board 估算另有設定。

自我檢查與理由

自我檢查

附件在全站啟用，但一人不能新增，先查哪項？

查看答案與理由

Create Attachments、工作可見性與欄位設定；不是只提高大小。

自我檢查

開啟board的Story points估算就等於人人可Log work嗎？

查看答案與理由

不是。估算與工時記錄分層，Log work還要對應權限與欄位。

自我檢查

輸入不帶單位的2被解成兩天，先檢查什麼？

查看答案與理由

全域default unit，並在操作規範明寫2h等單位。

自我檢查

LAB-1 blocks LAB-2，從LAB-2看應是什麼？

查看答案與理由

LAB-2 is blocked by LAB-1；同一關係的反向描述。

自我檢查

隱藏navigator link是否撤回遠端網站權限？

查看答案與理由

不會。導航可見性與遠端認證授權不同。
